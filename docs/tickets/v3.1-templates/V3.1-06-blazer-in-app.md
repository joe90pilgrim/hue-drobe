## Scope

**Goal.** Joe and B can put the blazer on the avatar in try-on and save it in an outfit. The pack already contains `blazer_male.glb` or `blazer_female.glb` (each pack has only its own sex's blazer), plus `tee_under_blazer_*.glb` (no faces) and `trousers_under_blazer_*.glb`, and the manifest lists them in `garments.inner_layers_drawn`. The existing `_under_` swap should handle the inner layers with no new viewer logic.

**Scope.**

- Add the two blazer files, and their under files, to every hand-kept file list (`viewer.ts`, `vite.config.ts`, and `deploy.mjs` / `make-test-pack.mjs` if they keep their own).
- Add `blazer_male` and `blazer_female` to `GARMENTS` under a new `Outer` slot, sex-limited like the skirt and dress, shown only when `viewer.has(mesh)`.
- Add the `Outer` rule to `keepLayers()` and a row in the try-on `SLOTS`.
- Add an optional `outer` field to `Outfit` and carry it through `OutfitLook`, `newOutfit`, `cleanOutfits`, `autoOutfitName` and `applyOutfit`. No version bump (hats and shoes did the same).
- Add a blazer flat-lay silhouette so saved outfits show an icon.

**Acceptance criteria.**

1. In try-on on Joe's pack, the blazer can be put on over a tee and trousers. On B's pack the same, using her blazer. Each person sees only their own blazer.
2. With the blazer on, the tee mesh is swapped for `tee_under_blazer_*` and the trousers for `trousers_under_blazer_*`. Taking the blazer off restores both. Show a screenshot of each state on Joe's and B's real packs (run locally from `private/`).
3. An outfit with a blazer saves, reloads and syncs; an old outfit with no `outer` still loads unchanged (Vitest).
4. The blazer file is in the service-worker precache and the deploy copy list (show the grep or test that proves it).
5. `keepLayers()` rules are covered by Vitest for each combination Joe chooses below.
6. One Playwright test: add the blazer, check the swap, remove it, check the restore, using stub GLBs in the fixture pack.
7. Full `npm run check` passes once before the final commit, with nothing else loading the machine.
8. Pack download size is unchanged from the 9.7 MB (Joe) and 14.6 MB (B) already measured, since no pack files are added.

**Decisions needed from Joe (stop and ask before starting).**

1. **Data model.** CLAUDE.md says to ask before changing it. This adds an optional `outer` field to the stored outfit record and a new `Outer` slot value in the stored outfit map. It is backwards compatible and needs no migration. Is that approved?
2. **Combinations.** May the blazer go over a tee or collared shirt only, or also over a sweatshirt? Does it stay on with a dress, skirt, shorts or tights, or must it give way? (The blazer was fitted over the tee and trousers only; anything else is untested.)
3. **Manifest.** The manifest has no `garments.blazers` entry (hats and shoes have one), and `layer: outer` and `hide_all` are not exposed. Default: hard-code the two names like the existing lists, with no pack change. Say if you would rather have a small manifest entry (that is a separate pack ticket).
4. **Splitting.** Default: this ticket covers try-on and saved outfits only. Packing, trips and Gemini matching get a follow-up if they need `outer`. Confirm.
