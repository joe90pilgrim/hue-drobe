# V1.1-06 Back up and restore your data (recommended addition)

**Ceiling:** 1 hour. The most this ticket may take, not a target. Stop as soon as the acceptance criteria are met.
**Worker:** Sonnet, low. Straightforward export and import, but it must handle every saved record type correctly.
**Depends on:** V1.1-02, V1.1-03

## Goal
Export everything the app stores to one file, and import it again, so saved items and outfits survive a cleared browser or a new phone.

## Scope
- Export: saved items, outfits, favourites, quiz result and current look, as one JSON file with a version number.
- Import: replaces the current data after a confirmation; rejects files it doesn't recognise.
- The avatar pack itself is not included (it's rebuilt or reinstalled separately).

## Decisions needed from Joe
- **Is this wanted in 1.1?** The blueprint listed backup as a must, and 1.1 is the first version where losing data would hurt (saved clothes and outfits). Recommendation: yes.

If a decision isn't made when this ticket starts, stop and ask rather than guess.

## Acceptance criteria
- Export, clear the app's storage, import: everything comes back.
- End-to-end test covers the round trip.

## Status
Built. The Wardrobe screen has a Back up card with Export backup and Import backup. The file is JSON (`format: huedrobe-backup`, `version: 1`) holding saved clothes, outfits, favourite colours, the quiz result, the current look (outfit, colours, neckline). Import checks the format and version, cleans each record with the same validators the app uses, asks before replacing, and clears anything the backup does not hold. The avatar pack is not included. `npm run check` passes (20 end-to-end tests, 1 new covering export, cleared storage, import and a rejected file; 2 new unit tests). Joe has not yet tried it on his phone.
