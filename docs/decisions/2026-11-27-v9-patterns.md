# Patterns on garments (27 Nov 2026)

Joe's decisions for Version 9, recorded with V9-01 (data and pickers). Nothing is drawn yet: V9-02 draws patterns in 2D, and V9-03 is a spike on whether 3D can show them.

## Joe's decisions

1. **2D first.** Patterns are drawn on the 2D paper-doll and garment tiles. The 3D avatar keeps showing the base colour for now.
2. **Two colours only.** The garment's own colour, plus one pattern colour.
3. **Every garment except shoes.** Tops, bottoms, tights, dress, blazer and hats can have a pattern. Shoes cannot, and neither can hair.
4. **Five options:** plain, horizontal stripes, vertical stripes, spots, flowers.

Decisions for V9-01 itself, answered by Joe in the session on 27 Nov 2026:

- Try On remembers patterns under a **new synced key `patterns`**, mirroring `colours`.
- Pattern words **go into auto-names** ("Navy striped tee"). Names already go to Gemini, so the word does too; the pattern fields themselves do not.
- The **Gemini packing payload and colour matching stay on base colour and name only**. `deploy/packing.mjs`, `app/src/packing-template.ts` and `app/src/match.ts` are unchanged, so the privacy record stands.
- Joe asked for **`CLAUDE.md` to be edited in this ticket** (the ticket had said he would do it himself). The new wording is below.

## Rule overturned

The 16 Nov 2026 decision "shape plus colour for garments; textures for hair and shoes only" (`docs/tickets/decisions-needed.md`, "Garment texture") no longer holds for the 2D view: garments may now carry a pattern in a second colour. The 3D avatar is still plain colour for garments, so the `CLAUDE.md` rule changes only in what it covers, as below. The decisions-needed entry is history and was not edited.

## Data shape

- **Pattern ids** (`app/src/patterns.ts`): `plain`, `hstripes`, `vstripes`, `spots`, `flowers`. `isPatternable(garmentId)` is true for every garment whose slot is not Shoes, false for shoes, `hair` and unknown ids.
- **Saved item** (`SavedItem`): optional `pattern` (any id except `plain`) and `patternColour` (lower-case hex). Both are omitted when the item is plain, so a plain item is byte-for-byte what it was. No version bump: an older record is simply plain, as with `sheer`. `cleanItems` drops both fields if the id is unknown, the colour is not a hex, only one of them is present, or the garment is a shoe.
- **Identity:** `ensureItem` includes pattern and pattern colour, so the same piece in two patterns, or in one pattern with two colours, is two items.
- **Try On state:** the `patterns` key holds `{ [garment id]: { pattern, colour } }`; a garment with no entry is plain. Like `colours`, it is keyed by garment id, so the Under slot's tee and the Top slot's tee share a pattern. `cleanPatterns` (also the backup cleaner) drops unknown ids, bad colours, shoes and `plain` entries.
- **Wearing:** `wearItem` and `wearOutfit` set the garment's pattern from the item, or clear it when the item is plain, so a plain item never inherits an earlier pattern. Garments an outfit does not use keep what they had, as colours do.
- **Outfits** hold item ids only and need no change.
- **Sync and backup:** `patterns` is in the backup key list and in `SYNC_KEYS` in `deploy/datastore.mjs`. Backup version stays 1.
- **Auto-name:** the pattern word (`striped`, `pinstriped`, `spotted`, `floral`) goes after the colour. If that would pass the 40-character name limit (for example "Light orange pinstriped short-sleeve shirt", 42), the word is left out and the pattern still shows in its own fields.
- **First pattern colour:** white on a dark base, near-black (`#1a1a1a`) on a light one, judged by luma (below 0.5 is dark). After that the garment's last pattern colour comes back within the session.

## Rollout risk

The server must be redeployed before the app, or the new `patterns` key is refused (404) and stays unsynced. An older app build open on another device would drop the new item fields when it re-saves. Joe and Beth should refresh the app after deploy. **Do not deploy V9-01 alone:** the controls change nothing visible until V9-02.
